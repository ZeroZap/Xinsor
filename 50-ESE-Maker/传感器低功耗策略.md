# 传感器低功耗策略

> **一句话描述:** 把传感器功耗从“芯片电流”扩展为采样策略、唤醒链路和恢复成本的系统问题  
> **标签:** `#ESE` `#低功耗` `#传感器`  
> **状态:** 提炼稿  
> **最后更新:** 2026-06-06

---

## 核心观点

低功耗不是简单把传感器设为 sleep。系统要同时考虑测量周期、唤醒延迟、数据新鲜度、总线恢复、校准状态和上层业务响应。很多传感器在频繁启动/停止时反而不稳定或更耗能。

---

## 模式对比

| 模式 | 适合场景 | 风险 |
|------|----------|------|
| continuous | 高频、低延迟、融合 | 平均功耗高 |
| forced/single shot | 环境慢变量、周期采样 | 需要等待转换完成 |
| FIFO batch | IMU、功耗与数据量平衡 | timestamp 和溢出处理复杂 |
| interrupt wake | 门限/事件唤醒 | 阈值调参和误触发 |
| full power off | 超低频测量 | 状态丢失、预热和重新校准 |

---

## 类型差异

| 类型 | 低功耗注意点 |
|------|--------------|
| 温湿度 | 单次测量友好，但冷凝/加热器影响数据 |
| IMU | wake-on-motion、FIFO、水位中断优先考虑 |
| 气体 | 预热、baseline 和算法状态不适合频繁断电 |
| 光学 | LED/VCSEL 脉冲功耗、积分时间、环境光 |
| 电源监测 | 采样周期影响 energy/mAh 统计准确性 |

---

## 接口建议

| 接口 | 说明 |
|------|------|
| `set_mode()` | sleep/forced/continuous/fifo |
| `set_odr()` | 采样率独立配置 |
| `wait_ready()` | 避免盲 delay |
| `save_state()` | 保存 baseline/校准/配置 |
| `restore_state()` | 唤醒后恢复上下文 |
